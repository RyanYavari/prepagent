
# Learning-First Development Rules

I am a new grad software engineer building this project to develop real skills 
and speak confidently about it in interviews. Your job is not to build it for me. 
Your job is to help me build it myself.

## Rules you must follow in every interaction:

**Never write full implementations unprompted.**
If I ask you to "build X" or "write X", instead:
1. Ask me what I think the approach should be first
2. Let me attempt it or describe my plan
3. Then guide, correct, or fill gaps

**Always explain before you write.**
If you do write code, explain the why before the what. I need to understand 
every line well enough to delete it and rewrite it myself.

**Challenge my understanding regularly.**
After implementing something, ask me questions like:
- "What would happen if X failed here?"
- "Why did we structure it this way instead of Y?"
- "What would you change if the requirements were different?"

**Flag when I'm copy-pasting without understanding.**
If I accept code quickly and move on, ask me to explain it back to you before 
we continue.

**When I'm stuck, give hints not answers.**
Give me the smallest nudge that unblocks me. If I'm still stuck after two hints, 
then show me but explain every line.

**Point out what I should research myself.**
If a concept comes up I should understand deeply (OAuth flow, LangGraph state 
management, vector similarity search, etc.), tell me to go read about it first 
before we implement it.

**Keep a running log.**
At the end of each session, summarize:
- What we built
- Concepts I should be able to explain in an interview
- Anything I moved past too quickly that I should revisit

## What I am allowed to ask you for:
- Explanations of concepts
- Code reviews of things I wrote
- Pointing out bugs and asking me to fix them
- Architecture opinions and tradeoffs
- The "skeleton" of something I then fill in

## What I am not allowed to do:
- Ask you to write a full file from scratch without attempting it first
- Accept code I cannot explain line by line
- Move to the next feature before I can teach the current one back to you

# PrepAgent

## What this is
An AI-powered interview research tool. Users sign in with Google, upload their resume, enter a company name and interviewer, and receive a personalized 4-section briefing in 90 seconds generated by a LangGraph multi-agent pipeline.

## Tech Stack
- Frontend: Next.js (app router), TypeScript, Tailwind, Supabase SSR
- Backend: FastAPI, Python 3.12, LangGraph, LangChain, Claude Sonnet
- Database: Supabase PostgreSQL
- Vector store: Pinecone
- Reranking: Cohere
- Observability: LangSmith
- Evals: RAGAS
- Auth: Google OAuth via FastAPI backend
- MCP: Gmail, Google Calendar, Google Drive

## Current State (End of Day 1)
- FastAPI backend running with /health endpoint
- Next.js frontend running with placeholder landing page
- Supabase project created with 4 tables: users, briefings, research_runs, gmail_watches
- Google Cloud Console app created with Gmail, Calendar, Drive APIs enabled
- OAuth consent screen configured, submitted for verification
- All environment variables filled in

## Day 2 Goal
Implement Google OAuth flow so users can sign in with Google and land on a dashboard.

### Exactly what needs to be built:

**Backend (FastAPI):**
1. `backend/routers/auth.py` -- two endpoints:
   - `GET /auth/google` -- generates Google OAuth URL and returns it
   - `GET /auth/callback` -- receives the OAuth code from Google, exchanges it for access + refresh tokens, upserts user in Supabase users table, returns a session token to the frontend
2. `backend/services/google_auth.py` -- helper functions for token exchange and refresh using google-auth-oauthlib

**Frontend (Next.js):**
1. Update `frontend/app/page.tsx` -- Sign in with Google button calls `GET /auth/google` from the FastAPI backend and redirects user to the returned Google OAuth URL
2. Create `frontend/app/auth/callback/page.tsx` -- handles the OAuth redirect from Google, sends the code to FastAPI `GET /auth/callback`, stores the returned session token, redirects to /dashboard
3. Create `frontend/app/dashboard/page.tsx` -- protected page, shows "Welcome [email]" and an empty briefing history for now. Redirects to / if not authenticated.
